Optimizer 写路径层间流动语义

本表描述 write/insert、write touch、驱逐下沉、selective 下写，以及 hierarchical engine 到 storage pool 的写入流动。

阶段 条件 状态更新 层间行为 统计/后续处理
写前 TTL 处理 每次 write 开始前 移除 TTL 过期 location 只做逻辑过期；空节点物理清理延迟到本次请求结尾 进入本次写入
写入新 block radix tree 中不存在该 key，或该 block 已被完全驱逐 初始化 block writing_time、last_access_time、TTL；入口 tier 初始化 tier stat 按相邻 edge 的 write_mode 决定初始落哪些 tier，并记录 ENTER_TIER 计入 newly inserted blocks，记录 block birth
write_through 初始写 相邻 edge write_mode = write_through 入口 tier 初始化 write_touch_count = 1；写穿到低层的副本初始化 write_touch_count = 0 沿连续 write-through edge 复制到所有经过的低层 每个落地 tier 注册到自己的 eviction policy
cascading 初始写 相邻 edge write_mode = cascading 只在入口 tier 初始化写入状态 不在写入时落下一层；后续由容量驱逐触发下沉 低层没有副本时不会占用容量
write_through_selective 初始写 相邻 edge write_mode = write_through_selective 只在入口 tier 初始化写入状态 不在初始写入时落下一层；后续由 write touch 阈值触发下写 下写阈值由 selective_write_threshold 控制
写命中已有 block 写入 key 已存在且仍有 location block last_access_time = now；最高已有 tier 执行 write touch 不创建更高层新副本；只对当前最高已有 tier 计一次真实 write touch 计入 write hit，不计 newly inserted
write touch 某 tier 已有该 block，并且本次写路径触达该 tier 该 tier last_access_time = now，write_touch_count += 1 刷新 eviction policy 中该 tier 的冷热位置，并记录 WRITE_TOUCH write touch 不改变 writing_time
向下 write propagation 低层已有副本，且相邻 edge 的 write_propagation_enabled = true 刷新所有连续可达的低层已有副本冷热，不增加 write_touch_count 只 touch 已有副本，不创建低层新副本，并记录 WRITE_TOUCH(WRITE_PROPAGATION) 不触发低层 selective；某条 edge 关闭后，更低层也不再传播
selective 下写 某 tier 的 write_touch_count >= selective_write_threshold，且该 edge 是 selective 被复制到下一层的 tier 使用当前时间初始化，write_touch_count = 0 下一层缺失时复制，已存在时跳过副本创建；后续 write-through edge 仍继续向下流动 由 write touch 触发，不由 read 触发
写后容量检查 本次 write/下写结束后 驱逐策略按各 tier 当前冷热选择 victim 分层模式按 tier 顺序从高层到低层检查容量 驱逐出的路径进入 eviction bookkeeping
cascading 驱逐下沉 某 tier 发生容量驱逐，且到下一层 edge 是 cascading 下一层不存在该 block 时复制到下一层，write_touch_count = 0；已有则保持已有副本 已存在的目标层不重复建副本；后续 write-through edge 仍继续向下流动 最后一层驱逐后记录 FINAL_EVICT
写穿/ selective edge 上的驱逐 某 tier 发生容量驱逐，edge 不是 cascading 只删除被驱逐 tier 的 location，并记录 LEAVE_TIER 不做驱逐下沉 block 仍可能在其他 tier 存活
写后统一清理 本次 write/下写/容量驱逐结束后 清理本次 TTL/容量驱逐后已经没有 location 的 block 统一裁剪空 block 和空叶子节点 生命周期淘汰信息在最终驱逐时记录

Hierarchical engine → storage pool

storage_pool_flow.write_mode engine 写入 storage pool 写入 storage pool 已有副本 说明
write_through trace write 先写 engine 本次写入在 engine pool-source 层产生的 ENTER_TIER/真实 WRITE_TOUCH 写入 storage pool shadow_write_touch_enabled 控制是否对 pool 已有副本做 write touch WRITE_PROPAGATION 不作为写入 pool 的来源
cascading engine 发生最终驱逐 engine 侧产生 FINAL_EVICT 的 block 写入 storage pool 驱逐下沉写入 pool 时不做已有副本 touch 驱逐写由 eviction 驱动，不限定触发 eviction 的请求类型
write_through_selective trace write 只写 engine 本次写入在 engine pool-source 层产生 ENTER_TIER/真实 WRITE_TOUCH，且写触达次数达到阈值后，将对应 prefix 写入 storage pool shadow_write_touch_enabled 控制写入 pool 时已有副本是否 write touch 传播 touch 不累加阈值，也不触发 selective pool 写入
统一写入形态 所有 engine → pool 写入策略 写入 storage pool 时传完整 prefix path，并用 materialized_indices 标识真正落地的 block 未 materialize 的 prefix key 只作为 radix tree anchor 适配写穿、selective、驱逐下沉产生的非当前请求 block
pool 内部多层 engine 只决定哪些 keys 进入 pool 写路径 pool 内部按自己的 tier_flows 决定写穿、驱逐下沉和 selective pool 内部已有副本的 write touch 仍由 pool 自己的写路径执行 engine → pool 的 flow 不替代 pool 内部多层 flow
